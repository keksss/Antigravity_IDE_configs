# Тестовый набор для скила `markdown-to-docx`

## Назначение
Автоматизированный комплексный тестовый набор для валидации скила `markdown-to-docx`. Проверяет 100% покрытие синтаксиса Markdown при конвертации в Microsoft Word (`.docx`), чистоту структуры OpenXML, корректность работы со стилями и шаблонами, сквозную интеграцию со скилом `docx-editor` и валидность открытия сгенерированных документов через реальный Microsoft Word COM с экспортом в PDF.

---

## Архитектура тестов и сценарии

Тестовый раннер `run_tests.py` выполняет 11 изолированных сценариев:

1. **Scenario 01: Headings & Hierarchy**
   - Проверка заголовков всех уровней (`#` до `######` -> `Heading 1` до `Heading 6`).
   - Поддержка русскоязычных и кириллических заголовков.
   - Проверка структуры документа и иерархии разделов.

2. **Scenario 02: Full Inline Formatting**
   - Инлайн форматирование: жирный (`**`), курсив (`*`), жирный+курсив (`***`), зачеркивание (`~~`), моноширинный код (`` ` ``).
   - Глубоко вложенные комбинации (жирный текст с вложенным курсивом и кодом).
   - Мягкие переносы строк (`softbreak`) с сохранением пробелов между словами.
   - Жесткие переносы строк (`hardbreak`, `\`) с формированием разрывов `<w:br/>`.

3. **Scenario 03: Hyperlinks & Anchors**
   - Кликабельные внешние ссылки Word (`<w:hyperlink>`) с генерацией связей `r:id`.
   - Поддержка богатого форматирования текста ссылки (`[**Жирная ссылка**](...)`).

4. **Scenario 04: Lists & Hierarchies**
   - Маркированные списки (`-`, `*`) и нумерованные списки (`1.`, `2.`).
   - Многоуровневая вложенность (3+ уровня).
   - Списки задач и интерактивные чекбоксы: `- [ ]` -> `☐ ` и `- [x]` / `- [X]` -> `☑ `.

5. **Scenario 05: GFM Tables & Alignment**
   - Таблицы GitHub Flavored Markdown с выравниванием колонок (`:---`, `:---:`, `---:`).
   - Повторение строки заголовка таблицы на каждой новой странице (`w:tblHeader`).
   - Защита строк от разрыва между страницами (`w:cantSplit`).
   - Затенение фона заголовка (`#F2F4F7`) и инлайн-форматирование внутри ячеек.

6. **Scenario 06: Blockquotes & Callouts**
   - Обычные и многопараграфные цитаты (`>`).
   - Алерты GitHub-style (`> [!NOTE]`, `> [!TIP]`, `> [!IMPORTANT]`, `> [!WARNING]`, `> [!CAUTION]`).
   - Акцентные цветные левые бордюры (`w:pBdr`), фоновое затенение (`w:shd`), бейджи и поддержка богатого форматирования Markdown внутри алертов.

7. **Scenario 07: Code Blocks & Syntax**
   - Блоки кода с указанием языка (Python, JSON и др.).
   - Сохранение 4-пробельных и табуляционных отступов.
   - Оформление: моноширинный шрифт Consolas, светло-серый фон (`#F4F5F7`), левый акцентный бордюр (`#0969DA`).

8. **Scenario 08: Images & Aspect Ratio**
   - Внедрение растровых изображений PNG с сохранением естественных пропорций (Aspect Ratio) и DPI через библиотеку Pillow.
   - Центрирование изображений в параграфе.
   - Корректная обработка отсутствующих файлов без прерывания генерации.

9. **Scenario 09: Template Inheritance (`--template`)**
   - Использование внешнего референсного `.docx` документа как шаблона.
   - Очистка тела старого документа при сохранении секций, полей, стилей, колонтитулов и ориентации.
   - Заполнение шаблона новым содержимым из Markdown.

10. **Scenario 10: Chained Workflow with `docx-editor`**
    - Демонстрация разделения ответственности: конвертация Markdown в `.docx` через `markdown-to-docx`, последующая инспекция структуры через `docx_inspect.py`, контекстная замена текста и добавление согласующего параграфа через `docx_edit.py`.
    - Проверка создания резервной копии `.docx.bak`.

11. **Scenario 11: Document Validity & Microsoft Word COM Automation**
    - Проверка OpenXML ZIP-целостности (наличие `word/document.xml`).
    - Проверка открытия всех сгенерированных документов в реальном Microsoft Word через COM Automation (`win32com.client.Dispatch("Word.Application")`).
    - Экспорт контрольного документа в PDF подтверждает 100% готовность к печати и отсутствие структурных дефектов.

---

## Запуск тестов

### Запуск полного набора `markdown-to-docx`:
```bash
uv run tests/docx-tools/markdown-to-docx/run_tests.py
```

### Запуск общего мастер-раннера для всех плагинов:
```bash
uv run tests/run_all.py --plugin docx-tools
```

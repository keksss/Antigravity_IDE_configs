# docx-editor Skill

Safely inspect and modify existing Microsoft Word (`.docx`) files in-place while preserving document styles, fonts, margins, headers, footers, and table formats.

---

## Environment Setup

This skill uses Python with `python-docx`. Dependencies are defined via PEP 723 metadata in the script header.

Execute scripts using either:
1. **With `uv` (Recommended):**
   ```bash
   uv run scripts/docx_inspect.py <path_to_docx>
   uv run scripts/docx_edit.py <path_to_docx> <action> [args]
   ```
2. **With Python and local virtual environment:**
   If `.venv` does not exist in this skill folder, create it:
   ```bash
   # Windows
   python -m venv .venv
   .\.venv\Scripts\pip install python-docx
   .\.venv\Scripts\python scripts/docx_edit.py <path_to_docx> <action> [args]

   # Linux/macOS
   python -m venv .venv
   ./.venv/bin/pip install python-docx
   ./.venv/bin/python scripts/docx_edit.py <path_to_docx> <action> [args]
   ```

## Best Practice Workflow: Inspect Before Editing

Before modifying a document, inspect its structure and styles so you can reference existing styles and headings accurately:

```bash
# 1. View document outline and headings
uv run scripts/docx_inspect.py document.docx --mode outline

# 2. View available styles in the document
uv run scripts/docx_inspect.py document.docx --mode styles

# 3. View tables structure
uv run scripts/docx_inspect.py document.docx --mode tables
```

### Post-Processing Documents Generated by `markdown-to-docx`
When a document has been created from Markdown via `markdown-to-docx`, use `docx-editor` for all subsequent fine-tuning:
- Applying corporate branding or specific font styles
- In-place text replacements or template variable insertions
- Modifying table structures or appending certified signature/approval paragraphs

## Safe Editing Operations

All editing commands automatically create a `.docx.bak` backup copy before writing changes.

### 1. Replace Text (Preserving Run Formatting)
Replaces text throughout paragraphs and table cells without losing bold, italic, font colors, or font sizes:
```bash
uv run scripts/docx_edit.py contract.docx replace-text --find "ООО Старое Название" --replace "ООО Новое Название"
```

### 2. Append Paragraph (Inheriting Styles)
Appends a new paragraph to the end of the document. If `--style` is omitted, it inherits the style of the last paragraph:
```bash
uv run scripts/docx_edit.py report.docx append-paragraph --text "Документ согласован юридическим отделом." --style "Normal"
```

### 3. Insert Paragraph After Specific Anchor / Heading
Inserts content immediately after a specific heading or anchor paragraph:
```bash
uv run scripts/docx_edit.py spec.docx insert-after --anchor "2. Требования к безопасности" --text "2.1 Все данные должны шифроваться по стандарту AES-256."
```

### 4. Add Row to an Existing Table
Adds a new row to table `N` (0-indexed), inheriting cell font and borders from the row above:
```bash
uv run scripts/docx_edit.py invoice.docx add-table-row --table-index 0 --values "3" "Консультационные услуги" "1" "50 000"
```

## Template Rendering with Jinja2 (`docx_render.py`)

Generate dynamic documents from Word templates using Jinja2 syntax via `docxtpl`. Supports variables (`{{ client }}`), table row loops (`{% tr for item in items %}`), conditionals (`{% if is_discount %}`), and inline images.

### Inspect Template Variables
Discover what variables a `.docx` template expects:
```bash
uv run scripts/docx_render.py template.docx --inspect-vars
```

### Render Template from JSON File or CLI
```bash
# From JSON file
uv run scripts/docx_render.py template.docx -d context.json -o output.docx

# From inline JSON
uv run scripts/docx_render.py invoice_tpl.docx --json '{"client": "ООО Ромашка", "total": "150 000 руб."}' -o invoice.docx
```

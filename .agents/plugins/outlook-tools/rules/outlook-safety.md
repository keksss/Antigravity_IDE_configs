# Правила безопасности при работе с Microsoft Outlook (`outlook-tools`)

При выполнении операций с почтовым клиентом Microsoft Outlook через плагин `outlook-tools`, агент **ОБЯЗАН** строго соблюдать следующие правила безопасности.

---

## 1. Обязательное подтверждение отправки писем (Draft-First & Confirm)

1. **Никогда не отправлять письмо сразу:**
   - Даже если пользователь пишет: *«Отправь письмо клиенту/коллеге...»*, агент **КАТЕГОРИЧЕСКИ НЕ ИМЕЕТ ПРАВА** сразу вызывать команду с флагом `--send`.
   - Первым шагом агент **всегда** создает черновик с флагом `--draft` (поведение по умолчанию для `mail_compose.py`).

2. **Обязательная карточка черновика в чате:**
   - После создания черновика агент выводит пользователю структурированную карточку:
     - **Кому (To):** `...`
     - **Копия (CC):** `...`
     - **Тема (Subject):** `...`
     - **Вложения:** `...`
     - **Текст письма:** (цитата или краткое содержание)
     - **ID черновика (EntryID):** `...`
   - Агент задает прямой вопрос:
     > *«Черновик письма сохранен в Outlook. Вы подтверждаете отправку данного сообщения?»*

3. **Итеративное редактирование без дублей:**
   - Если пользователь просит внести правки (*«Поправь второй абзац»*, *«Добавь в копию менеджера»*), агент использует команду редактирования черновика по ID:
     ```bash
     uv run scripts/mail_compose.py --id <entry_id> --body "Новый текст"
     ```
   - Запрещено создавать новые дублирующие черновики, если уже есть созданный ID.

4. **Выполнение отправки:**
   - Команда с флагом `--send` вызывается **ТОЛЬКО** после того, как пользователь прямо в чате написал подтверждение («Да», «Отправляй», «Ок», «Согласен»).
   - На системном уровне вызов команды с `--send` дополнительно контролируется хуком `hooks/safety_check.py` (`PreToolUse: force_ask`).

---

## 2. Обязательное подтверждение отмены и удаления (Delete & Cancel)

1. **Запрет автоматического удаления:**
   - Агент **никогда** не удаляет письма, черновики, контакты или записи календаря в автоматическом режиме.
2. **Процедура удаления/отмены:**
   - Перед вызовом команд с флагами `--cancel` или `--delete` агент обязан:
     1. Показать пользователю точные реквизиты удаляемого элемента (тема, дата, отправитель/участники, ID).
     2. Запросить подтверждение: *«Вы уверены, что хотите отменить/удалить эту встречу/письмо?»*.
     3. Выполнять команду только при утвердительном ответе.

---

## 3. Конфиденциальность и обработка данных

1. **Аккуратный вывод содержимого писем:**
   - При чтении писем не выводить в чат избыточные служебные заголовки, нечитаемые бинарные данные или огромные простыни неформатированного HTML.
   - Использовать извлеченный чистый текст (`body_text`) или конвертированный Markdown.
2. **Изоляция вложений:**
   - При сохранении вложений (`--save-attachments`) сохранять файлы строго в изолированные каталоги проекта (например, в `.scratch/` или `downloads/`). Не сохранять файлы в корень рабочей директории или системные папки.

---

## 4. Надежность и управление COM-ресурсами

1. **Освобождение ссылок MAPI:**
   - Все скрипты взаимодействия с Outlook должны в блоке `finally:` освобождать COM-объекты и вызывать `pythoncom.CoUninitialize()`, предотвращая утечки дескрипторов и блокировки файлов данных (`.ost` / `.pst`).
2. **Обработка неактивного Outlook:**
   - Скрипты должны корректно обрабатывать сценарий, когда клиент Outlook не запущен, пытаясь подключиться через `GetActiveObject` с мягким фоллбеком на `Dispatch("Outlook.Application")`.
